# Bizzmind — състояние на проекта

_Обновено: 25.08.2026. Този файл е пълната картина за продължаване на работата в нова сесия._

## Какво е продуктът

SaaS за нетехнически търговски екипи: качваш ексели → AI ги проучва и те интервюира
(интерактивни въпроси с кликаеми опции) → строи жив дашборд с филтри → генерира
брандирана презентация като от човек. Еталонната цел е описана в **SPEC.md**
(реалният проект sidaya-analytics).

## Стартиране

```bash
cd ~/Repos/"Analytics Project"

# продукция: AI_BACKEND=api (иска Anthropic API кредити)
```

- Landing: http://127.0.0.1:8000/ · Приложение: /app · Вход: george@inceptiq.ai (парола при George)
- Потребители: data/users.json (PBKDF2), сесии: data/sessions.json (30 дни, httponly cookie)
- Логове: `server.log` — всяка стъпка е с префикс `STEP |` (upload, ingest, всеки AI tool call
  с време и статус, refresh, auth, deck, brand extract)
- Рестарт дисциплина: `pkill -f "uvicorn app:app"` + изчакване + `pkill -9`; **зомбита се
  случват** — винаги проверявай `pgrep -f uvicorn | wc -l` == 1. НЕ рестартирай докато George
  тества (предупреди първо). Сървърът държи проектното състояние в паметта — редакция на
  JSON по диска изисква рестарт.

## Архитектура

- **app.py** (~2000 реда, единствен backend файл): FastAPI + DuckDB (per-проект база) +
  Claude Agent SDK (subscription) / Anthropic API (продукция) + auth middleware.
- **static/app.html** — цялото приложение (vanilla JS + ECharts CDN). **static/landing.html**,
  **static/login.html**. No-cache хедъри на трите страници (Chrome кешираше стар JS).
- **Проект = изолирана среда** в `data/projects/<id>/`: project.duckdb, chat.json, notes.json
  (знание), filters.json, dashboard.json, meta.json (име, files→tables карта, views описания),
  uploads/ (оригиналите), brand/ (лого, brand book, brand.json с цветове+шрифтове), PROGRESS.md.
- **Двуслоен модел на данните**: сурови таблици (landing zone от файловете) + семантични
  **views** (`v_*`, чисти бизнес колони на български) — графиките и филтрите гледат САМО
  views; при нови файлове AI обновява дефиницията на view-то и нищо не се чупи.
  ВНИМАНИЕ: съществуващите проекти (sidaya-pharma, poli-demo, demo-pharma) са строени ПРЕДИ
  този слой — миграция: кажи в чата „Изгради семантични изгледи и превържи дашборда към тях“.
- **AI инструменти** (общи за двата бекенда): run_sql_query (read-only + {{токени}}),
  record_data_context (знание), define_view / drop_view, define_filter (multi/single,
  {{token}} експанзия), create_chart / update_chart / delete_chart, verify_dashboard
  (ЗАДЪЛЖИТЕЛЕН последен tool при промени — изпълнява всяка графика под 3 комбинации
  селекции), present_questions (интервю форми с опции; UI-ът винаги позволява мулти-избор).
- **Промптове**: PROMPT_INTRO / PROMPT_INTERVIEW (3 стъпки: разбери данните → разбери какво
  иска потребителят → строй: views→филтри→графики) / PROMPT_RULES (двуслойното правило,
  Dashboard UX standard, label readability, филтри, verify mandate). Subscription сесията
  получава схема+знание+бранд в <data_context> на всяко съобщение; при рестарт — recap на
  последните 14 съобщения.

## Функционалности (всичко работещо)

- **Ingestion**: заглавни редове (детекция по плътност), двуредови хедъри (2024+10→_2024_10),
  кирилица в колоните, дублирани имена, CSV/XLSX мулти-листове; оригиналите се пазят.
- **Интервю**: опционална пред-анализ форма след качване (какво знам + какво целя);
  въпроси с опции (всички са мулти-избор + „✎ Друг отговор“ добавъчно); отговорите → знание.
- **Дашборд**: живи филтри (multi dropdown-и + single превключватели), cross-filter при клик
  върху бар/резен/точка (повторен клик маха), drag&drop пренареждане (⠿), badge „+N“ за нови
  графики, „table“ тип = широка карта през целия ред със sticky header.
- **Рендер стандарт**: класации/дълги имена → автоматично хоризонтални барове с динамична
  височина; rotate+hideOverlap+съкращаване на оси; пай: minShowLabelAngle 5°, hideOverlap;
  scatter точките носят име (първата текстова колона) с етикети.
- **Данни таб**: database browser — списък таблици/изгледи (🧩), типове на колоните,
  сортиране по колона, търсене, странициране, inline редакция на клетки (не за views) →
  графиките се преизчисляват веднага.
- **Знание таб**: бележките се виждат/редактират (клик)/трият/добавят ръчно; брояч бейджове.
- **Чат**: плаващ overlay (не бута съдържанието), 💬 fab при скрит, автоотваряне при AI
  работа, жив процес-фийд (всяка стъпка + секунди), auto-grow textarea; целият разговор
  персистира; състоянието на чата/таба се помни в localStorage.
- **Бранд**: качване на лого (PNG/JPG - изрично, НИКОГА автоматично от книгата) + brand book
  PDF → автоматично: текст, **цветова гама** (hex + „R: G: B:“ разбивки), **шрифтове**
  (речник от познати имена, whole-word match — „Internet“≠Inter). Прозрачни превюта в UI.
  Помощни варианти на логото се правят при поискване (napr. navy: тъмнина→алфа + запълване).
- **Презентация („📽 Презентация“)**: AI пише deck spec JSON (заглавия-послания с числа,
  наратив 2-3 изречения без тирета, 2-4 секции, agenda, takeaways; всяка графика точно
  веднъж) → HTML A4 слайдове → html2canvas(scale 2) → jsPDF. Брандирано: цветовете от
  книгата (примари/акцент + гамата като серии в графиките), шрифтът от книгата (Google
  Fonts зареждане с fallback), логото на корицата. Графиките се пре-рендират офскрийн в
  светла печатна тема (никога тъмните от дашборда). Reportlab endpoint /export/pdf
  съществува като сървърен fallback, но не се ползва от UI.
- **Верификация**: GET /api/p/{pid}/verify — механичен тест на целия дашборд.
- **Проекти**: списък/създаване/преименуване (PUT /api/projects/{pid})/триене; миграция от
  legacy формат; backfill-ове (files карта, brand extraction) при първо отваряне.

## Стандарти (заковани в PROMPT_RULES — НЕ ги разводнявай)

Двуслойното правило · обобщаваща таблица най-отгоре · канонични филтри без дубликати
(преизползвай id-та!) · всяка графика вързана към всички приложими филтри · бизнес език
на езика на потребителя · месеци хронологично · label readability (top-N + Other) ·
инкрементални промени (не гигантски rebuild — таймаутът е 600 s) · verify преди „готово“ ·
целта на потребителя е под, не таван (предлагай открития, не добавяй самоволно).
